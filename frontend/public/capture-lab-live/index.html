Thread A/B — hold the camera still

Runs 10 s at the selected thread cap and records the resolved camera size, the detector input, the median inference and detections/s. Each line is keyed by cap · camera · input, so rerunning a combination replaces it; the repeat buttons offer another cap or input so you can compare.

    The ring is dashed while the detector is tracking and solid for a moment when a usable detection lands. The worker is the app's own cardDetector.worker.js, resolved from the build manifest; it is asked for the selected thread cap (1 / 2 / 4 / 8, default min(4, hardwareConcurrency)) as WASM threads only when this document is cross-origin isolated and SharedArrayBuffer exists. Changing the cap restarts the worker, so the A/B helper compares like-for-like without a reload. The camera size is renegotiated on the live track and the detector input resizes the next frame, so neither restarts the worker or drops the ring. Blur outside the card: ….
